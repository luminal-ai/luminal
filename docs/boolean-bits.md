# Boolean encoding operations

`LogicalBitsToBools(input)` exposes the encoding of each element as one-bit `Bool` values, least-significant bit first. Its shape is the input shape with a final axis of length `bits-of(dtype-of(input))`. This width excludes layout padding. Bit addresses increase from the least-significant to the most-significant encoding bit within each cell; this is an explicit logical placement convention, independent of host byte order. A backend using a different native bit order must translate that representation before claiming a view. Logical `Bool` is one bit, while `Bool8` is an eight-bit code with exactly two legal encodings: 0 and 1. The Rust author's existing `DType::Bool` denotes logical Bool; its byte boundary representation remains unchanged. `DType::logical_bits()` makes the distinction explicit without changing the existing storage API.

`LogicalBoolsToBits(input, A)` accepts one-bit Bool values and packs consecutive groups along the last axis. It preserves rank, dividing the last extent by the target encoding width. Rank-zero inputs and known non-divisible extents are rejected. The Rust frontend requires divisibility to be provable when recording; the IR derives a shape only after divisibility is proved. Unpack followed by pack leaves a final singleton axis. A squeeze recovers the original shape. The operations perform encoding conversion, never numeric casts. Signed integers use two's complement; floating inputs retain signed zero, subnormals, infinity and NaN payload bits. This does not specify the payload chosen by an arithmetic instruction that produces a new NaN.

`LogicalAnd`, `LogicalOr` and `LogicalNot` accept only Bool or Bool8. Binary operands have equal shapes and equal dtypes; the output preserves both. Broadcasting and representation conversion are explicit. Byte-Boolean complement maps 0 to 1 and 1 to 0; it never complements all eight storage bits. The Rust convenience methods author one-bit Boolean algebra. Bool8 is already available in the logical/binding vocabulary and is covered directly at that seam.

## Placement and proofs

For an input bit-offset map `p(c)`, splitting derives the read-only view `p(c) + k` with access width one. Strided input elements are allowed; bits outside the input element's encoding are never exposed.

Packing to width `w` derives the view start `q(c,j) = p(c,w*j)` only when egglog proves `p(c,w*j+k) = q(c,j)+k` throughout the group domain. The proof uses the existing guarded coordinate substitution and a demand-local certificate that the grouped address is affine in the bit lane with unit slope. Coefficients use BigInt facts; proving the property does not introduce arithmetic reassociations into the e-graph. Gaps between groups and strided outer axes are allowed. Gaps, reversal, or broadcasts within a group prevent the view. Restricted Bool8 target encodings currently always materialize and validate the complete code; they never take an unproved view route.

The reference registry offers separate materializing and metadata-view implementations. A view declares a required storage tie, no reads and no writes, and grants no overwrite permission. The planner can relocate the tied storage under its existing alias rules. Materializers assemble destination encodings directly in a canonical output layout. No blanket contiguous-input copy is inserted. Core only derives layout facts; runtime-owned matchers select executable implementations.

Reference kernel matches require canonical write layouts, matching their existing dense write ABI; claiming a strided write while writing a dense vector would make a subsequent bit view unsound. The executor checks that write capability for externally loaded plans too.

The reference executor keeps owning buffers typed. Consumers of bit views project their logical values through the elected bit-address map into the existing dense kernel ABI. That projection uses host scratch and is included in memory accounting; the view itself allocates no intermediate buffer. The existing `get_*` convenience API supplies dense typed readback for escaped views. `output_slot` retains the original shared backing buffer and the elected layout. This is a correctness reference, not a packed-kernel performance implementation.

No conversion cancellation or floating numerical-equality rewrite is introduced. Floating add/multiply operand permutation is no longer an unconditional e-graph equality, because NaN payload selection can depend on operand order. Integer commutativity remains available. Backend floating optimizations must likewise preserve the observable encoding contract before selecting an alternative.

Reference execution supports the dtypes it can already allocate (Bool/Bool8, I8/U8/I16, Int/Int64/UInt64, F32/F64 and F8E4M3FN). The logical operations are width-generic, including sub-byte encodings; this change does not add reference arithmetic/storage for other dtypes, PyTorch translations, or CUDA/Trainium kernels.
